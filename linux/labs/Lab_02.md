# Lab 02 — Управление процессами

## Цель:

научиться находить, анализировать, контролировать и убивать процессы в Linux — от базового `ps` до сигналов, приоритетов, фоновых задач и зомби-процессов.

## Часть 1 — Наблюдение за процессами.

<mark>+</mark> Выведем в терминале снапшот всех процессов
![ps_aux](lab_02_pics/Снимок%20экрана%20—%202026-07-29%20в%2013.59.46.png)
![ps_aux_1](lab_02_pics/Снимок%20экрана%20—%202026-07-29%20в%2013.59.59.png)

команда **ps** выводит снапшот процессов, запущенных в момент выполнения команды.
**Что выводит эта команда?**
На скриншотах видно несколько полей:

- USER — чьими правами обладает процесс
- PID _(process ID)_ — айди процесса
- %CPU — процент использования ЦПУ
- %MEM — процент использования оперативной памяти
- VSZ _(Virtual Memory Size)_ — сколько виртуальной памяти зарезервировал процесс
- RSS _(Resident Set Size)_ — фактический объем оперативной памяти, выделенной процессу
- TTY _(Teletypewriter)_ — Терминал, к которому привязан процесс
- STAT _(Status)_ — Статус процесса (R, S, D, Z, I -- +, s, l, <, N)
- START — Время запуска процесса
- TIME — Время, затраченное процессом на вычисления
- COMMAND — Имя программы/полный путь к файлу

Разберём флаги этой команды:

- a _(all)_ — показывает процессы, принадлежащие всем пользователям
- u _(user-oriented)_ — подробный формат вывода
- x — показывает процессы, у которых нет терминала (демоны, фоновые службы и т.д.)
- f _(forest)_ — отобразить в виде дерева
- -e (every process)
- -f _(full format)_

_Обратите внимание на_
_TTY: ? — это процессы без терминала (демоны, фоновые службы)_
_TTY: pts/tty — pts — псевдотерминал, эмулирующий терминал в окне_

<mark>+</mark> Разберёмся, как наблюдать за процессами в реальном времени
Команда `top` позволяет открыть таблицу процессов, меняющуюся в реальном времени
![top](lab_02_pics/Снимок%20экрана%20—%202026-07-29%20в%2014.16.38.png)

большинство колонок уже знакомы:

- PID
- USER
- PR _(priority)_ приоритет процесса **PR = 20 + NI**. Чем больше число, тем меньше приоритет. **rt** обозначает, что процесс работает в реальном времени _(real time)_, значит у него максимальный приоритет
- NI _(niceness)_ значение, влияющее на приоритет. \[-20, 19]
- VIRT _(virtual image)_ — VSZ из ps aux
- RES _(resident size)_ — RSS из ps aux
- SHR _(shared memory)_ — объём разделяемой памяти, которую использует процесс с другими процессами в системе
- S _(Status)_
- %CPU
- %MEM
- TIME+COMMAND
  Также сверху можно найти много полезной информации о системе.

![htop](lab_02_pics/Снимок%20экрана%20—%202026-07-29%20в%2014.18.09.png)

<mark>+</mark> Посмотрим процессы в папке _/proc_
Каждый процесс представлен в виртуальной файловой системе. Папка _/proc_ — срез состояния внутри ядра в реальном времени. Через _/proc_ `top` и `htop` получают информацию о системе.

Например, в файле `status` мы можем обнаружить имя процесса, состояние, айди, айди родителя, uid/gid и т.д.

### Команды

- ps (auxf, -ef)— вывод процессов
- pstree (-pls) — вывод дерева процессов системы
- top — таблица процессов, обновляемая в реальном времени
- htop — улучшенная таблица процессов, обновляемая в реальном времени
- pgrep (-afuc) — вывод процессов по имени
- папка `/proc`

| Критерий / Поле                                    | killall                                                   | pkill                                                             |
| -------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------- |
| Принцип поиска процесса                            | Точное совпадение имени файла процесса.                   | Поиск по шаблону (подстрока или RegExp).                          |
| Пакет-поставщик                                    | psmisc                                                    | procps / procps-ng (совместно с pgrep)                            |
| Уровень риска                                      | 🟢 Низкий. Убьёт только то, что на 100% совпало по имени. | 🟡 Высокий. Можно случайно зацепить лишние процессы по подстроке. |
| Чувствительность к регистру                        | Да (по умолчанию).                                        | Да (по умолчанию).                                                |
| Игнорирование регистра                             | -I (или --ignore-case)                                    | -i                                                                |
| Поиск по полному командному строке (с аргументами) | ❌ Не умеет (ищет только по имени процесса).              | ✅ -f (ищет аргументы, например: pkill -f "python main.py").      |
| Фильтрация по пользователю                         | -u <user>                                                 | -u <user>                                                         |
| Фильтрация по возрасту процесса                    | -o (старше) / -y (моложе)                                 | -o (самый старый) / -n (самый новый PID)                          |
| Интерактивный режим (с подтверждением)             | ✅ -i (спрашивает y/n перед каждым PID).                  | ❌ Отсутствует.                                                   |
| Аналог для предварительной проверки                | Отсутствует                                               | pgrep (использует те же флаги поиска, но не убивает).             |

### Часть 4 — Фоновые задачи и управление Job'ами

<mark>+</mark> Научимся выводить процессы на передний и задний план
![bg/fg](lab_02_pics/Снимок%20экрана%20—%202026-07-30%20в%2016.07.25.png)
**&** — запускаем процесс в фоновом режиме
**fg** _(foreground)_ — на передний план
**bg** _(background)_ — на задний план
**`% <num>`** — номер процесса в списке `jobs`

<mark>+</mark> **`nohup` и `disown`**

команда `nohup` защищает процесс от `SIGHUP` при закрытии сессии и обычно перенаправляет вывод в `nohup.out`, поэтому если случится ошибка и терминал закроется, процесс будет существовать дальше.
![nohup](lab_02_pics/Снимок%20экрана%20—%202026-07-30%20в%2016.08.53.png)

вывод команды автоматически переходит в _nohup.out_, проверим:
![nohup.out](lab_02_pics/Снимок%20экрана%20—%202026-07-30%20в%2016.08.43.png)

так и есть.

Если процесс уже запущен, но нужно выключить терминал, то спасает `disown`
команда вычёркивает процесс из таблицы jobs (`disown` убирает job из контроля shell).
![disown](lab_02_pics/Снимок%20экрана%20—%202026-07-30%20в%2016.11.16.png)

разница между `nohup` и `disown`:

| Критерий             | nohup                                                  | disown                                       |
| -------------------- | ------------------------------------------------------ | -------------------------------------------- |
| Когда применять      | При запуске новой команды                              | Для уже запущенной job                       |
| Что делает           | Игнорирует `SIGHUP` и обычно пишет вывод в `nohup.out` | Убирает job из таблицы `jobs` текущего shell |
| Нужен ли job control | Нет                                                    | Да (работа через `jobs/%n`)                  |
| Типичный сценарий    | `nohup long_task &`                                    | `Ctrl+Z` → `bg` → `disown`                   |

### Команды

- & — запуск задачи сразу в фоне
- jobs — список job текущего shell
- fg %N — вернуть задачу `N` на передний план
- bg %N — продолжить задачу `N` в фоне
- ` nohup <cmd> &` — запуск с игнорированием `SIGHUP`
- disown %N — убрать задачу из job-таблицы shell
