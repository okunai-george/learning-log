# Lab 03 — Файловая система

## Цель:

разобраться, как Linux видит диски и устройства, как устроена файловая система изнутри (inode, ссылки, точки монтирования), и научиться вручную создавать, монтировать и проверять файловые системы — не как «чёрный ящик», а с пониманием того, что происходит на каждом шаге.

## Часть 1 — Иерархия файловой системы (FHS)

<mark>+</mark> Заглянем в корневой каталог и определим, за что отвечает каждая директория:![/](lab_03_pics/Снимок%20экрана%20—%202026-08-23%20в%2019.08.43.png)

- . — указатель на текущую директорию
- .. — указатель на родительскую директорию. (если перейти из корня, то останешься там же)
- afs _(Andrew File System)_— распределённая сетевая файловая система
- bin _(binary)_ — директория с готовыми к запуску программ и системных утилит (cat, mkfs, curl, etc)
- boot — файлы загрузчика и ядра, необходимые для загрузки системы
- builddir — каталог для временных или промежуточных файлов, создаваемых при компиляции и сборке программ
- dev _(devices)_ — специальные файлы устройств, через которые можно обращаться к аппаратному обеспечению компьютера (диски, терминалы и т. д.)
- etc — файлы настроек системы и программ
- home — директория с домашними папками пользователей системы
- lib _(library)_ — каталог с библиотеками, необходимыми программам и системе
- lib64 — каталог с библиотеками для 64-битных программ
- media — точки монтирования для съёмных устройств (USB-флешек и т. д.)
- mnt — точка для временного ручного монтирования файловых систем
- opt _(optional)_ — каталог дополнительного и стороннего программного обеспечения
- proc _(processes)_ — виртуальная файловая система с информацией о процессах и состоянии ядра
- root — домашняя папка админа
- run — временная энергозависимая информация, относящаяся только к текущему сеансу (PID-файлы, сокеты и т. д.)
- sbin _(system binary)_ — системные бинарные файлы для настройки и восстановления системы
- srv _(services)_ — данные, предоставляемые службами
- sys _(system)_ — виртуальная файловая система для просмотра и настройки оборудования, драйверов и ядра
- tmp _(temporary)_ — временные файлы, созданные ОС и программами
- usr _(unix system resources)_— основные пользовательские приложения, утилиты, библиотеки и документация
- var _(variable)_ — изменяющиеся данные (системные журналы, кэш, базы данных и файлы сайтов)

> [!Заметим]
> В системах с UsrMerge `bin` обычно является символической ссылкой на `/usr/bin`, а `sbin` — на `/usr/sbin`. От разделения каталогов отказались, потому что оно потеряло свой технический смысл (раньше в них хранился минимальный набор программ из-за ограничения места в корневом разделе). Процесс объединения каталогов называется UsrMerge.
>
> Помимо `bin` и `sbin`, под UsrMerge могут подпадать каталоги `lib` и `lib64`.
>
> (Что-то может отличаться на других дистрибутивах)

<mark>+</mark> Посмотрим, что лежит в /etc/fstab
![/etc/fstab](lab_03_pics/Снимок%20экрана%20—%202026-08-23%20в%2021.05.22.png)

`fstab` _(file systems table)_ — системный файл с описанием файловых систем, которые могут монтироваться автоматически. Разберём его поля:

1. Устройство или источник файловой системы
2. Точка монтирования:
   > <уникальный код диска UUID>
   > <точка монтирования>
   > <тип файловой системы>
   > <Параметр монтирования> (default, ro (read-only), etc)
   > <Дамп> (устаревший параметр утилиты `dump`: 0 — не использовать, 1 — использовать)
   > <Порядок проверки `fsck`> (0 — не проверять; 1 — проверять первым; 2 — проверять после файловых систем с приоритетом 1)

> [!About Dump]
> Dump — устаревшая технология, использовавшаяся с файловой системой ext2. На текущий момент есть более современные технологии бэкапов

## Часть 2 — Диски и устройства в /dev

<mark>+</mark> Посмотрим вывод устройств в /dev, разберём типы устройств:
![/dev](lab_03_pics/Снимок%20экрана%20—%202026-08-23%20в%2021.06.26.png)

В строке с правами можно увидеть разные первые буквы:

- c/u _(character)_ — символьное устройство, передаёт данные как поток байтов
  - /dev/null — отбрасывает записанные данные и возвращает EOF при чтении
  - /dev/zero — файл, заполненный нулями
  - /dev/random — файл с хаосом (псевдорандом)
- b _(block)_ — блочное устройство, передаёт данные фиксированного размера (блоками).
  - /dev/sda
  - /dev/nvme0n1p1
- l _(symlink)_
- d _(directory)_

> [!Вы больше не увидите в /dev]
>
> - s _(socket)_ — сокет для межпроцессного взаимодействия
> - p _(pipe)_ — именованный канал FIFO для передачи данных между процессами
>   Сокеты и именованные каналы могут находиться в разных каталогах, часто в `/run` и `/tmp`.
>   В `/dev` обычно находятся устройства, а не обычные сокеты и именованные каналы.

<mark>+</mark> Посмотрим на формат вывода блочных и символьных устройств

Перед датой в выводе есть 2 числа: Старший номер **(Major number)** и Младший номер **(Minor number)**

Major number — идентифицирует тип устройства или драйвер, обслуживающий его. Значения зависят от ядра и подсистемы устройств: например, традиционные устройства `sd*` часто используют major `8`, а NVMe — `259`.

Minor number — обозначает конкретный экземпляр устройства или его раздел. Его значение зависит от схемы нумерации конкретного драйвера и не обязано совпадать с номером раздела.

<mark>+</mark> Посмотрим на дерево блочных устройств
Введём `lsblk`
![lsblk](lab_03_pics/Снимок%20экрана%20—%202026-08-23%20в%2021.09.39.png)

- Name — имя диска
- Major:Minor numbers
- RM _(Removable)_ — флаг съёмного устройства (0 — не съёмное, 1 — съёмное)
- Size — размер диска
- Type — тип блочного устройства
- Точка монтирования

## Часть 3 — создание виртуального диска

<mark>+</mark> Создадим файл-образ диска размером 500 Мб
![virtual disk](lab_03_pics/Снимок%20экрана%20—%202026-08-24%20в%2012.20.53.png)

```bash
dd if=/dev/zero of=~/virtual_disk.img bs=1M count=500
```

- dd — поблочное копирование и преобразование данных
- if — input file
- of — output file
- bs — block size
  Итог: скопировать из файла с нулями в файл `virtual_disk.img` 500 блоков размером 1 МиБ.

<mark>+</mark> Сделаем файл с нулями диском
(подключим этот файл как loop-устройство, чтобы ОС работала с ним как с диском)

```bash
    sudo losetup -fP ~/virtual_disk.img
    losetup -a
```

флаги:

- f _(find)_— находит свободное имя (пример loop0)
- P _(partscan)_ — сканирует таблицу разделов и создаёт устройства разделов, если они есть
- a _(all)_— показывает все занятые loop-устройства

> [!Hardlink]
> Хардлинк — это дополнительная запись каталога, указывающая на ту же inode, что и исходное имя файла. В разных файловых системах независимые таблицы inode, поэтому хардлинк между двумя файловыми системами невозможен.

<mark>+</mark> Экспериментируем с symlink

**Команды**

- `ln <origfile> <hardlink>` — создать хардлинк
- `ln -s <origfile> <symlink>` — создать симлинк
- `ls -i` — посмотреть файлы с номерами инод
