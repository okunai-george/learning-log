Посмотреть информацию о пароле пользователя можно командой __chage -l__, модификатор -l показывает список (list) параметров пароля:
![[Снимок экрана — 2026-07-22 в 19.32.37.png]]

В данном примере у пользователя _alina_:
+ Дата последней смены пароля: 22 июля 2026 года
``` bash
sudo chage -d YYYY-MM-DD <username>
```
+ Дата истечения пароля: никогда (можно задать временной период, когда нужно сменить пароль)
+ Период неактивности: никогда (временной период, дающийся на смену пароля после его истечения. После этого аккаунт блокируется полностью)
```bash
sudo chage -I <days_naumber> <username>
```
+ Дата окончания действия аккаунта: никогда (дата, после которой аккаунт заблокируется)
```bash
sudo chage -E YYYY-MM-DD <username>
```
+ Минимальный интервал смены: 0  (сколько минимум дней должно пройти, чтобы пользователь смог снова поменять пароль)
```bash
sudo chage -m <days_number> <username>
```
+ Максимальный интервал смены: 99999 (показывает, через сколько дней пароль обязательно должен быть изменён. Параметр 99999 — пароль вечный)
```bash
sudo chage -M <days_number> <username>
```
+ Период предупреждения : 7 (кол-во дней до даты истечения пароля, за которое система будет предупреждать пользователя о смене пароля)
```bash
sudo chage -W <days_number> <username>
```

Разберём пару флагов _usermod_:
+ -l (_login)_ — изменить имя пользователя. При этом имя домашней директории не меняется (нужен флаг -d)
```bash
sudo usermod -l <old_name> <new_name>
```
  + -u _(uid)_ — принудительно меняет айди пользователя
  ```bash
sudo usermod -u <number> <username>
  ```
+ -c _(comment)_ — изменить поле комментария
```bash
sudo usermod -c "<comment>" <username>
```
+ -d _(home dir)_ — изменить домашную директорию
```bash
sudo usermod -d <path> <username>
```
+ -s _(shell)_ — изменить командную оболочку по умолчанию
```bash
sudo usermod -s <term> <username>
```
если в поле _term_ указать _/sbin/nologin_, то доступ к терминалу будет заблокирован
+ -g _(group)_ — задать основную группу
```bash
sudo usermod -g <group> <username>
```
+ -G _(group)_ — задать дополнительную группу
```bash
sudo usermod -G <group> <username>
```
+ -aG _(append group)_ — добавить дополнительную группу
```bash
sudo usermod -aG <group> <username>
```
+ -L _(lock)_ — заблокировать пароль пользователя

```bash
sudo usermod -L <username>
```
+ -U _(unlock)_  — разблокировать пароль пользователя
```bash
sudo usermod -U <username>
```

![[Снимок экрана — 2026-07-23 в 21.06.02.png]]
разберём команду _chown_:
+ chown _(choose owner)_ — команда, позволяющая изменить владельца-пользователя или владельца-группу файлов или директорий.
```bash
sudo chown <username> <filename> # сменяет владельца у 1 файла
sudo chown <uid> <filename>  # сменяет владельца по айди
sudo chown <username>:<groupname> <filename> # задаёт пользователя и группу одновременно
sudo chown <uid>:<gid> <filename> 
```
Также существует команда _chgrp_:
+ chgrp _(change group)_ команда, позволяющая изменить владельца-группу файлов или директорий.
```bash
sudo chgrp <groupname> <filename> # сменяет владельца у 1 файла
sudo chgrp <gid> <filename>  # сменяет владельца по айди
```

! Если нужно изменить не только владельца директории, но и всех файлов/подпапок в ней используется флаг __-R__ _(recursion)_

Сделаем так, чтобы папки были читаемы/изменяемы/исполняемы владельцем и группой, остальным пользователем — ничего

chmod _(change mod)_ инструмент управления правами доступа к файлам/директориям.

на данном скриншоте представлен символьный способ изменения прав:
`u/g/o` (user, group, other) ± `r/w/x` (read, write, execute)
добавить: +, убрать: -

также можно прописывать изменения прав числовым способом:
![[Снимок экрана — 2026-07-23 в 21.13.46.png]]
где каждому праву присвоена цифра
+ 4 = read
+ 2 = write
+ 1 = execute
+ 0 = nothing

Права складываются в одну цифру для каждой из 3 категорий
+ **7** = 4 + 2 + 1 (`rwx` — полные права)  
- **6** = 4 + 2 + 0 (`rw-` — чтение и запись)  
- **5** = 4 + 0 + 1 (`r-x` — чтение и выполнение)  
- **4** = 4 + 0 + 0 (`r--` — только чтение)

==+== Установим SUID-бит так, чтобы файл, запускаемый пользователем, выполнялся с правами `root` 
что такое __SUID-бит?__ 
__SUID__ _(set user id)_ — специальный бит прав доступа, который позволяет пользователю запускать исполняемый файл с правами владельца этого файла.
Напишем простой скрипт с командой "echo "deploy running as $(whoami)"
сделаем его исполняемым и владельцем `root`
![[Снимок экрана — 2026-07-23 в 21.45.46.png]]
в правах можно заметить `s`, она сигнализирует о __SUID__
![[Снимок экрана — 2026-07-23 в 21.52.43.png]]
при исполнении скрипта от пользователя _vera_ выводится _vera_. Почему так? Казалось бы, должно было вывести `root`. Спросим у Gemini:
`_SUID-бит был успешно установлен (буква s отображается в ls -l), однако при запуске от пользователя vera команда whoami вернула vera. Это подтверждает, что ядро Linux из соображений безопасности игнорирует SUID-бит для интерпретируемых shell-скриптов_`

Создавать __SUID__ на shell скриптах является опасной практикой, потому что злоумышленники могут воспользоваться уязвимостью системы, чтобы исполнить зловредный код (подменить скрипт(__Race Condition__) или внедрить вредоносные функции через переменные среды.
