# Devices

Как Linux представляет физические и виртуальные устройства в виде файлов.

---

## 1. /dev directory — Директория /dev

В Linux действует принцип "всё — файл" (everything is a file). Устройства — не исключение: ядро представляет диски, терминалы, принтеры и прочее железо в виде специальных файлов внутри `/dev`.

```bash
ls -l /dev

```

```
Вывод: список файлов-устройств — sda, tty1, null, random, nvme0 и т.д.

```

- Файл в `/dev` — это не сам файл с данными, а **интерфейс** для общения с драйвером устройства через обычные системные вызовы (`read`, `write`, `open`)
- Благодаря этому одни и те же команды (`cat`, `cp`, перенаправления) работают и с обычными файлами, и с железом
- `/dev` — это viртуальная файловая система (`devtmpfs`), она пересоздаётся при каждой загрузке и не хранится на диске как обычные файлы

## 2. Device Types — Типы устройств

При `ls -l /dev` первая буква строки показывает тип: `b` — block device, `c` — character device. Плюс отдельно существуют pipe и socket — тоже "файлы", но не для железа, а для связи между процессами.

```bash
ls -l /dev/sda /dev/tty1

```

```
Вывод:
brw-rw---- ... /dev/sda   (b = block device)
crw-rw-rw- ... /dev/tty1  (c = character device)

```

### Block device — Блочное устройство

Работает с данными **блоками фиксированного размера** (например, по 4 КБ) и поддерживает произвольный доступ — можно сразу прыгнуть к нужному блоку, не читая всё по порядку. Данные буферизуются ядром для скорости.

```bash
Примеры: /dev/sda (диск), /dev/nvme0n1 (SSD-раздел), /dev/loop0

```

- Аналогия: **книга с оглавлением** — можно открыть сразу на любой странице (блоке), не листая с начала

### Character device — Символьное устройство

Работает с данными **потоком байт**, последовательно, без буферизации и без возможности "перемотать назад" в произвольное место.

```bash
Примеры: /dev/tty1 (терминал), /dev/random, /dev/null, /dev/nvme0

```

> **Важный пример: `/dev/nvme0`** Это не сам диск с данными (тот находится в `/dev/nvme0n1`), а **символьное устройство-контроллер** — интерфейс администрирования самого NVMe-контроллера. Через него утилиты вроде `nvme-cli` шлют управляющие команды контроллеру (посмотреть состояние здоровья диска, температуру, настроить namespace), а не читают/пишут файлы. То есть `nvme0` работает как **"маршрутизатор" запросов к памяти** — управляющий канал к контроллеру, а не хранилище данных.

- Аналогия: **шланг с водой** — вода течёт непрерывным потоком, ты не можешь "перепрыгнуть" сразу к литру №50, только пропустить через себя весь поток по порядку

### Pipe — Именованный канал

Однонаправленный поток данных **между двумя процессами на одной машине**. По сути — файл-посредник: один процесс пишет в него, другой читает.

```bash
mkfifo mypipe # Создать именованный канал (named pipe / FIFO)

```

- Аналогия: **труба-переговорник на стройке** — один рабочий кричит в один конец трубы, другой слушает с другого конца. Оба должны быть на месте одновременно, и сообщение идёт строго в одну сторону

### Socket — Сокет

Двунаправленная точка связи **между процессами**, причём необязательно на одной машине — сокеты лежат в основе сетевого обмена (TCP/IP), но бывают и локальные (Unix domain socket).

```bash
Пример: /var/run/docker.sock (локальный сокет для общения с Docker)

```

- Аналогия: **телефонная линия** — оба абонента могут говорить и слушать одновременно, и неважно, сидят они в одной комнате или на разных континентах (в отличие от pipe, где связь — только "на одном столе" и в одну сторону)

## 3. Device Names — Имена устройств

### ⭐ SCSI — Small Computer System Interface

Большинство имён устройств хранения в Linux (`sda`, `sdb`, `sdc`...) происходят от драйвера **SCSI** — стандартного интерфейса, через который ядро видит диски, независимо от того, физически это SCSI, SATA, USB-флешка или даже виртуальный диск в облаке. Современный Linux почти все накопители "прогоняет" через SCSI-подсистему, поэтому имена `sdX` стали универсальными.

```bash
lsblk

```

```
Вывод: sda 8:0 disk, sda1 8:1 part /boot, sda2 8:2 part /

```

Разбор имени `sda1`:

```
sd  a  1
│   │  └── номер раздела (partition) на диске
│   └───── буква диска по порядку обнаружения (a — первый, b — второй...)
└───────── SCSI Disk (драйвер, через который диск виден системе)

```

- `sd` — SCSI disk: диск обслуживается SCSI-драйвером (сюда попадают и настоящие SCSI-диски, и SATA, и USB-накопители)
- `nvme0n1` — диски NVMe (подключаются напрямую по шине PCIe, минуя SCSI) называются иначе: `nvme` + номер контроллера (`0`) + `n` + номер namespace (`1`), например `nvme0n1p1` — первый раздел
- `sr0` — CD/DVD-привод (SCSI CD-ROM)

Псевдо-устройства (не физическое железо, а служебные интерфейсы):

```bash
/dev/null # "Чёрная дыра" — всё записанное туда исчезает
/dev/zero # Бесконечный поток нулевых байт
/dev/random # Источник случайных байт

```

## 4. sysfs — Виртуальная файловая система /sys

`/sys` — ещё одна виртуальная файловая система, которая выкладывает **информацию об устройствах и драйверах** в виде дерева файлов и папок. В отличие от `/dev` (интерфейс для _использования_ устройства), `/sys` — это интерфейс для _просмотра и настройки параметров_ устройства.

```bash
cat /sys/class/net/eth0/address

```

```
Вывод: MAC-адрес сетевой карты eth0

```

- `/sys` строится ядром на основе внутренней модели устройств (device model) — каждое устройство, драйвер и шина представлены папкой
- Многие файлы внутри можно не только читать, но и записывать в них — так меняют параметры устройств "на лету" без перезагрузки (например, яркость экрана: `/sys/class/backlight/.../brightness`)
- Разница коротко: **`/dev` — чтобы пользоваться устройством, `/sys` — чтобы узнать о нём и настроить его**

---

## 5. udev — Менеджер устройств

`udev` — подсистема, которая **динамически** создаёт и удаляет файлы в `/dev`, когда устройства подключаются или отключаются (флешка, мышь, диск).

```bash
udevadm info /dev/sda

```

```
Вывод: подробная информация об устройстве — атрибуты, родительские устройства, свойства

```

- Раньше `/dev` был статичным набором файлов на все возможные устройства заранее — udev решает эту проблему, создавая файл только когда устройство реально подключено
- Правила udev (в `/etc/udev/rules.d/`) позволяют задавать свои имена устройствам, права доступа или запускать скрипты при подключении (например, "при подключении вот этой флешки — всегда называть её `/dev/mybackup`")
- `udevadm monitor` — команда, чтобы в реальном времени смотреть события подключения/отключения устройств

## 6. lsusb, lspci, lsscsi — Просмотр устройств по шинам

Три команды, чтобы посмотреть, какое железо подключено к системе — каждая смотрит на свою шину (bus).

```bash
lsusb

```

```
Вывод: Bus 001 Device 003: ID 046d:c52b Logitech, Inc. Unifying Receiver

```

- `lsusb` — список всех устройств на шине **USB** (мышь, клавиатура, флешки, веб-камера)
- `lspci` — список устройств на шине **PCI/PCIe** (видеокарта, сетевая карта, NVMe-контроллер, звуковая карта)
- `lsscsi` — список устройств, видимых через **SCSI**-подсистему (диски `sdX`, CD/DVD), показывает связку с именем в `/dev`

```bash
lspci -v # (verbose) Подробный вывод с дополнительными деталями по каждому устройству
lsusb -v # Подробный вывод по USB-устройствам
lsscsi -s # (size) Показать ещё и размер каждого диска

```

- Эти команды читают информацию, которую ядро уже собрало (в т.ч. из `/sys`), просто показывают её в удобном виде — в отличие от `udevadm info`, который даёт детали по одному конкретному устройству

## 7. dd — Прямая побайтовая копия

`dd` (disk dump / "copy and convert") копирует данные напрямую, блок за блоком, из одного источника в другой — часто прямо в файл устройства, минуя файловую систему. Мощный, но опасный инструмент: ошибка в имени устройства может стереть не тот диск.

```bash
sudo dd if=ubuntu.iso of=/dev/sdb bs=4M status=progress

```

```
Вывод: побайтовая запись образа ubuntu.iso на флешку /dev/sdb, с индикатором прогресса

```

Ключевые параметры:

```bash
if= # (input file) Источник — файл или устройство, откуда читаем
of= # (output file) Приёмник — файл или устройство, куда пишем
bs= # (block size) Размер блока за одну операцию (влияет на скорость, обычно 4M-16M)
status=progress # Показывать прогресс копирования в реальном времени
count= # Ограничить количество копируемых блоков

```

Типичные примеры использования:

```bash
sudo dd if=/dev/sdb of=backup.img bs=4M # Сделать полный образ диска в файл
sudo dd if=/dev/zero of=file.img bs=1M count=100 # Создать пустой файл ровно 100 МБ (для тестов)
sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress # Склонировать один диск на другой один в один

```

> ⚠️ `dd` не спрашивает подтверждения и не проверяет, что ты пишешь — перепутать `of=/dev/sdb` с `of=/dev/sda` значит гарантированно уничтожить данные на системном диске. Всегда перепроверяй вывод `lsblk` перед запуском.
