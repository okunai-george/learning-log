# Processes

Работа с процессами, их состояниями, сигналами и приоритетами в Linux.

---

## 1. Процесс (Process) — что это

Запущенный экземпляр программы. У каждого процесса есть уникальный номер — PID.

```bash
echo $$

```

```
Вывод: PID текущей shell-сессии, например 4821

```

- PID (Process ID) — уникальный идентификатор процесса
- PPID (Parent Process ID) — PID родительского процесса, который его запустил
- Процесс с PID 1 — первый процесс в системе (обычно systemd), родитель для всех остальных

---

## 2. ps — Снимок процессов

Показывает список процессов в системе на текущий момент (в отличие от `top`, не обновляется в реальном времени).

```bash
ps aux

```

```
Вывод: таблица со всеми процессами системы — USER, PID, %CPU, %MEM, VSZ, RSS, TTY, STAT, START, TIME, COMMAND

```

Флаги:

```bash
ps -ef # альтернативный формат вывода (UNIX-style), показывает PPID
ps aux --sort=-%cpu # отсортировать по убыванию использования CPU
ps auxf # (forest) вывести процессы деревом, показывая родитель/потомок

```

Колонка `STAT` — состояние процесса:

```
R — running (выполняется)
S — sleeping (ждёт события)
D — uninterruptible sleep (ждёт ввод/вывод, не реагирует на сигналы)
T — stopped (остановлен)
Z — zombie (завершился, но родитель не забрал код завершения)

```

## 3. pgrep и pkill — Поиск и убийство процессов по имени

`pgrep` находит PID процессов по имени/шаблону, `pkill` сразу отправляет им сигнал.

```bash
pgrep firefox

```

```
Вывод: PID всех процессов с именем firefox

```

```bash
pkill firefox

```

```
Вывод: всем процессам firefox отправлен SIGTERM

```

Флаги:

```bash
pgrep -f "python script.py" # (full) искать совпадение по всей командной строке, а не только имени процесса
pgrep -u ivan # искать только среди процессов конкретного пользователя
pkill -9 firefox # отправить конкретный сигнал (здесь — SIGKILL) вместо TERM по умолчанию

```

---

## 4. top и htop — Мониторинг процессов в реальном времени

`top` — встроенный интерактивный монитор процессов, обновляется каждые несколько секунд. `htop` — более удобная версия с цветом и мышью (нужно ставить отдельно).

```bash
top

```

```
Вывод: живой список процессов, обновляется в реальном времени, сверху — общая статистика CPU и памяти

```

Горячие клавиши внутри `top`:

```
P — сортировать по % CPU
M — сортировать по % памяти
k — убить процесс (спросит PID и сигнал)
q — выйти

```

```bash
sudo dnf install htop # установка htop на Fedora
htop

```

## 5. kill — Отправка сигналов процессу

Отправляет процессу сигнал по его PID. Без указания сигнала по умолчанию отправляется `SIGTERM` (15) — "вежливая" просьба завершиться.

```bash
kill 4821

```

```
Вывод: процессу с PID 4821 отправлен SIGTERM

```

Флаги и сигналы:

```bash
kill -9 4821 # отправить SIGKILL — немедленное принудительное завершение, нельзя перехватить
kill -15 4821 # то же самое, что kill 4821 без флагов (SIGTERM)
kill -STOP 4821 # приостановить процесс (SIGSTOP)
kill -CONT 4821 # возобновить приостановленный процесс (SIGCONT)
kill -l # (list) показать список всех доступных сигналов с номерами

```

Основные сигналы:

```
SIGHUP  (1)  — historically "терминал отключился", часто используется как "перечитай конфиг"
SIGINT  (2)  — то, что посылает Ctrl+C
SIGKILL (9)  — немедленное убийство, нельзя перехватить или проигнорировать
SIGTERM (15) — вежливая просьба завершиться, сигнал по умолчанию
SIGSTOP (19) — принудительная пауза, нельзя перехватить
SIGCONT (18) — продолжить после паузы

```

- Всегда сначала пробуй `SIGTERM` — он даёт программе шанс корректно закрыться (сохранить файлы, закрыть соединения). `SIGKILL` обрывает процесс мгновенно, без возможности что-либо доделать.

## 6. killall — Убийство процессов по точному имени

Похож на `pkill`, но требует точного совпадения имени процесса (а не части имени или командной строки).

```bash
killall firefox

```

```
Вывод: всем процессам с именем firefox отправлен SIGTERM

```

Флаги:

```bash
killall -9 firefox # отправить SIGKILL вместо SIGTERM
killall -u ivan firefox # убить только процессы конкретного пользователя

```

## 7. nice и renice — Приоритет процессов

`nice` задаёт приоритет процессу при запуске, `renice` — меняет приоритет уже запущенного процесса. Диапазон — от `-20` (наивысший приоритет) до `19` (низший).

```bash
nice -n 10 some_command

```

```
Вывод: some_command запущена с nice-значением 10 (низкий приоритет, "уступчивый" процесс)

```

```bash
renice -n -5 -p 4821

```

```
Вывод: процессу с PID 4821 установлен nice -5 (более высокий приоритет)

```

- Понизить себе приоритет (уйти в положительные значения) может любой пользователь
- Повысить приоритет (уйти в отрицательные значения) может только root — иначе любой пользователь мог бы забрать себе весь CPU
- Название `nice` буквально означает "насколько процесс вежлив по отношению к другим" — чем выше число, тем охотнее процесс уступает CPU остальным

## 8. Управление job'ами — &, jobs, fg, bg

Job — задача, запущенная в текущей shell-сессии. `&` запускает команду в фоне сразу.

```bash
sleep 300 &

```

```
Вывод: [1] 4821 — номер job'а и его PID, команда работает в фоне

```

```bash
jobs

```

```
Вывод: список активных job'ов текущей сессии с их статусами

```

Управление:

```bash
fg %1 # (foreground) вернуть job номер 1 на передний план
bg %1 # (background) продолжить приостановленный job в фоне
Ctrl+Z # приостановить текущий процесс на переднем плане (отправляет SIGTSTP)

```

---

## 9. nohup и disown — Задачи, переживающие закрытие терминала

По умолчанию фоновые job'ы получают `SIGHUP` и завершаются при закрытии терминала. `nohup` и `disown` решают эту проблему по-разному.

```bash
nohup long_running_script.sh &

```

```
Вывод: скрипт продолжит работу после закрытия терминала, вывод уходит в файл nohup.out

```

```bash
long_running_script.sh &
disown

```

```
Вывод: job убирается из таблицы job'ов текущей shell — она перестаёт слать ему сигнал при закрытии

```

- `nohup` — не даёт сигналу `SIGHUP` дойти до процесса (перехватывает и игнорирует его)
- `disown` — убирает задачу из таблицы job'ов самой shell, поэтому shell вообще не пытается послать ей сигнал при выходе

## 10. /proc — Виртуальная файловая система процессов

Каждый процесс представлен папкой `/proc/<PID>/` — не файлы на диске, а "окно" в реальном времени в состояние процесса внутри ядра. Именно отсюда `ps` и `top` берут всю информацию.

```bash
cat /proc/$$/status

```

```
Вывод: подробный статус текущего процесса — состояние, память, uid/gid и т.д.

```

Полезные файлы внутри `/proc/<PID>/`:

```bash
cat /proc/PID/cmdline # команда, которой был запущен процесс
ls -la /proc/PID/fd # какие файлы/дескрипторы процесс держит открытыми
cat /proc/PID/environ # переменные окружения процесса

```

## 11. Зомби и осиротевшие процессы (Zombie & Orphan)

**Зомби** — процесс, который уже завершился, но родитель не вызвал `wait()`, чтобы забрать код завершения. Виден в `ps aux` как `STAT = Z` или `<defunct>` в конце команды.

```bash
ps aux | grep -w Z

```

```
Вывод: список зомби-процессов в системе (если есть)

```

- Зомби нельзя убить сигналом — он уже мёртв, ему нечем реагировать
- Чтобы избавиться от зомби, нужно завершить (или дождаться завершения) его родителя — тогда зомби "переусыновляется" процессом с PID 1, который автоматически его приберёт

**Осиротевший процесс (orphan)** — процесс, чей родитель завершился раньше него. Такой процесс не зомби — он продолжает нормально работать, просто получает нового родителя (обычно PID 1).

## 12. kill -0 — Проверка существования процесса

Специальный "нулевой" сигнал, который ничего не отправляет процессу, а просто проверяет, существует ли он и есть ли права его "тронуть".

```bash
kill -0 4821 && echo "жив" || echo "не найден"

```

```
Вывод: жив (если процесс с таким PID существует) или не найден

```

- Используется в скриптах-supervisor'ах для проверки, не упал ли процесс, без реального воздействия на него
