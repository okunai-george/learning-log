# Packages

Управление пакетами в Linux: как программы попадают на систему и как ими управлять.

---

## 1. Software Distribution — Распространение ПО

Пакет (package) — это архив с исполняемыми файлами программы, её конфигами и документацией, упакованный для удобной установки. Устанавливает, обновляет и удаляет пакеты **пакетный менеджер**.

```bash
apt show curl

```

```
Вывод: описание пакета curl — версия, зависимости, размер, откуда он

```

- **Upstream** — разработчики, которые пишут исходный код программы
- **Maintainer / Packager** — тот, кто упаковывает исходники в формат конкретного дистрибутива (`.deb`, `.rpm`) и следит за обновлениями
- Разные дистрибутивы используют разные форматы пакетов: `.deb` — Debian/Ubuntu, `.rpm` — Red Hat/Fedora/CentOS

---

## 2. Package Repositories — Репозитории пакетов

Репозиторий — удалённое хранилище пакетов, откуда их скачивает пакетный менеджер. Вместо загрузки программы с сайта разработчика систему настраивают на доверенные репозитории.

```bash
cat /etc/apt/sources.list

```

```
Вывод: список URL-адресов репозиториев, откуда apt берёт пакеты

```

- `/etc/apt/sources.list` — основной файл со списком репозиториев в Debian/Ubuntu
- `/etc/apt/sources.list.d/` — папка, куда обычно добавляют новые репозитории отдельными файлами (например, для стороннего ПО типа Docker)
- Каждая строка обычно указывает: тип (`deb`/`deb-src`), URL, релиз дистрибутива и компоненты (`main`, `universe` и т.д.)

## 3. tar и gzip — Архивирование и сжатие

`tar` объединяет несколько файлов в один архив (без сжатия), `gzip` сжимает файлы. Вместе часто дают `.tar.gz` — распространённый формат для исходников и бэкапов.

```bash
tar -czvf archive.tar.gz folder/

```

```
Вывод: создан сжатый архив archive.tar.gz из содержимого folder/

```

Флаги tar:

```bash
tar -c # (create) Создать архив
tar -x # (extract) Распаковать архив
tar -z # (gzip) Сжать/распаковать через gzip попутно
tar -v # (verbose) Показывать список файлов в процессе
tar -f # (file) Указать имя файла архива (почти всегда нужен последним)

```

```bash
tar -xzvf archive.tar.gz # Распаковать сжатый архив
gzip file.txt # Сжать файл (получится file.txt.gz, оригинал удалится)
gunzip file.txt.gz # Распаковать обратно

```

## 4. Package Dependencies — Зависимости пакетов

Многие пакеты для работы нуждаются в других пакетах (библиотеках). Это и есть зависимости — их нужно установить вместе с самим пакетом.

```bash
apt depends curl

```

```
Вывод: список пакетов, от которых зависит curl (libcurl4, libc6 и т.д.)

```

- Если ставить пакет вручную без учёта зависимостей — программа может не заработать ("dependency hell")
- Полноценные менеджеры (`apt`, `yum`) сами скачивают и устанавливают все зависимости по цепочке
- Низкоуровневые инструменты (`dpkg`, `rpm`) зависимости **не устанавливают** — только проверяют и сообщают, чего не хватает

---

## 5. rpm и dpkg — Низкоуровневые инструменты

Утилиты для работы с уже скачанным файлом пакета (`.rpm` или `.deb`) напрямую, без обращения к репозиториям.

```bash
sudo dpkg -i package.deb

```

```
Вывод: пакет package.deb установлен (или ошибка из-за отсутствующих зависимостей)

```

Флаги dpkg (Debian):

```bash
dpkg -i package.deb # (install) Установить пакет из файла
dpkg -r package_name # (remove) Удалить пакет
dpkg -l # (list) Показать все установленные пакеты
dpkg -L package_name # Показать список файлов, установленных пакетом

```

Флаги rpm (Red Hat):

```bash
rpm -i package.rpm # (install) Установить пакет из файла
rpm -e package_name # (erase) Удалить пакет
rpm -qa # (query all) Показать все установленные пакеты
rpm -ql package_name # (query list) Показать список файлов пакета

```

- Оба инструмента не решают зависимости сами — за это отвечают `apt`/`yum`

---

## 6. yum и apt — Высокоуровневые менеджеры пакетов

Обёртки над `rpm`/`dpkg`, которые дополнительно умеют скачивать пакеты из репозиториев и автоматически подтягивать все зависимости.

```bash
sudo apt install curl

```

```
Вывод: curl и все его зависимости скачаны и установлены

```

Флаги apt (Debian/Ubuntu):

```bash
apt update # Обновить локальный список доступных пакетов из репозиториев
apt upgrade # Обновить все установленные пакеты до последних версий
apt install pkg # Установить пакет вместе с зависимостями
apt remove pkg # Удалить пакет, оставив конфиги
apt purge pkg # Удалить пакет вместе с конфигами
apt search pkg # Найти пакет по имени/описанию

```

Флаги yum (Red Hat/CentOS/Fedora):

```bash
yum update # Обновить пакеты (или dnf update в новых версиях)
yum install pkg # Установить пакет с зависимостями
yum remove pkg # Удалить пакет
yum search pkg # Найти пакет

```

## 7. Compile Source Code — Сборка из исходников

Когда готового пакета нет в репозиториях, программу можно собрать вручную из исходного кода. Классическая связка — `./configure && make && make install`.

```bash
./configure
make
sudo make install

```

```
Вывод: программа собрана и установлена в систему из исходников

```

- `./configure` — скрипт проверяет систему (наличие компиляторов, библиотек) и готовит настройки сборки под неё
- `make` — компилирует исходный код в исполняемые файлы согласно `Makefile`
- `make install` — копирует собранные файлы в системные папки (обычно `/usr/local/bin` и т.п.)
- Минус этого способа: пакетный менеджер ничего не знает о такой программе — обновлять и удалять её придётся вручную
