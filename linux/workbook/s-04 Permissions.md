# Permissions

Права доступа к файлам и директориям в Linux: кто может читать, писать и выполнять.

---

## 1. Reading Permissions — Чтение прав доступа

У каждого файла и папки есть три категории "кому можно" (владелец, группа, остальные) и три вида прав (чтение, запись, выполнение). Посмотреть их можно через `ls -l`.

```bash
ls -l file.txt

```

```
Вывод: -rwxr-xr-- 1 grigorijklopov staff 1234 Jul 20 10:00 file.txt

```

Разбор строки прав `-rwxr-xr--`:

```
- rwx r-x r--
│  │   │   └── other (остальные): чтение
│  │   └────── group (группа): чтение + выполнение
│  └────────── user (владелец): чтение + запись + выполнение
└───────────── тип файла (- файл, d директория, l симлинк)

```

- `r` (read) — читать содержимое файла / список файлов в папке
- `w` (write) — изменять файл / создавать-удалять файлы в папке
- `x` (execute) — запускать файл как программу / заходить внутрь папки (`cd`)
- `-` — соответствующее право отсутствует
- После прав в выводе `ls -l` идут: количество жёстких ссылок, владелец, группа, размер, дата изменения, имя

## 2. Modifying Permissions — Изменение прав (chmod)

`chmod` (change mode) меняет права доступа. Есть два способа задать их: символьный и числовой (октальный).

### Символьный способ

```bash
chmod u+x script.sh

```

```
Вывод: владельцу добавлено право на выполнение

```

- `u` (user), `g` (group), `o` (other), `a` (all) — кому меняем права
- `+` добавить, `-` убрать, `=` установить ровно такие права (остальные сбросить)

```bash
chmod g-w file.txt # Убрать у группы право записи
chmod o=r file.txt # Оставить у "остальных" только чтение
chmod u+x,g+x script.sh # Несколько изменений через запятую

```

### Числовой (октальный) способ

Каждое право — это число: `r=4`, `w=2`, `x=1`. Числа складываются, получается одна цифра на категорию.

```bash
chmod 755 script.sh

```

```
Вывод: rwxr-xr-x (владелец: 4+2+1=7, группа: 4+1=5, остальные: 4+1=5)

```

Частые комбинации:

```bash
chmod 644 file.txt # rw-r--r-- (обычный файл: владелец пишет, остальные читают)
chmod 755 script.sh # rwxr-xr-x (исполняемый файл или папка)
chmod 700 secret.sh # rwx------ (только владелец может что-либо делать)
chmod -R 755 folder/ # (recursive) Применить рекурсивно ко всей папке и её содержимому

```

## 3. Ownership Permissions — Владение (chown, chgrp)

`chown` меняет владельца (и опционально группу) файла, `chgrp` меняет только группу.

```bash
sudo chown ivan file.txt

```

```
Вывод: владельцем file.txt стал ivan

```

```bash
sudo chown ivan:developers file.txt # Сменить и владельца, и группу разом
sudo chown :developers file.txt # Сменить только группу (через chown)
sudo chgrp developers file.txt # Сменить только группу (отдельной командой)
sudo chown -R ivan:developers folder/ # (recursive) Рекурсивно для всей папки

```

- Обычный пользователь не может передать файл другому владельцу — для `chown` нужны права root (`sudo`)
- Сменить группу на свою собственную обычный пользователь может и без sudo, если состоит в целевой группе

## 4. Umask — Права по умолчанию

`umask` задаёт, какие права **вычитаются** у новых файлов и папок при создании — это маска, а не сами права.

```bash
umask

```

```
Вывод: 0022

```

- По умолчанию система пытается дать файлам права `666` (rw-rw-rw-), а папкам `777` (rwxrwxrwx)
- Из этого значения umask вычитает биты — например, `022` уберёт право записи у группы и остальных
- Результат: новый файл получит `666 - 022 = 644`, новая папка — `777 - 022 = 755`

```bash
umask 027 # Установить новую маску для текущей сессии
umask -S # (Symbolic) Показать маску в виде u=rwx,g=rx,o=

```

## 5. Setuid — Смена эффективного пользователя (SUID)

Специальный бит: если он установлен на исполняемом файле, программа запускается с правами **владельца файла**, а не того, кто её запустил.

```bash
ls -l /usr/bin/passwd

```

```
Вывод: -rwsr-xr-x 1 root root ... /usr/bin/passwd

```

- Буква `s` вместо `x` в позиции владельца — это и есть SUID
- Классический пример — команда `passwd`: обычный пользователь запускает её от своего имени, но она выполняется с правами root, чтобы суметь изменить системный файл `/etc/shadow`

```bash
chmod u+s program # Установить SUID символьно
chmod 4755 program # То же самое числом (4 — код SUID, добавляется перед основными тремя цифрами)

```

---

## 6. Setgid — Смена эффективной группы (SGID)

Похожий бит, но для группы. На файле работает так же, как SUID (запуск с правами группы-владельца). На папке — особая логика.

```bash
ls -l /usr/bin/wall

```

```
Вывод: -rwxr-sr-x 1 root tty ... /usr/bin/wall

```

- Буква `s` в позиции группы — это SGID
- На **директории** SGID означает: все новые файлы, создаваемые внутри, автоматически получают группу этой директории, а не основную группу создателя — удобно для общих рабочих папок

```bash
chmod g+s program # Установить SGID символьно
chmod 2755 shared_folder/ # То же самое числом (2 — код SGID)

```

## 7. Process Permissions — Права процессов

Каждый запущенный процесс работает от имени какого-то пользователя и группы — это определяет, какие файлы и ресурсы он может трогать.

```bash
ps -eo pid,user,group,comm

```

```
Вывод: список процессов с указанием, от чьего имени каждый из них запущен

```

- У процесса есть **реальный** (real) UID/GID — кто его запустил, и **эффективный** (effective) UID/GID — с какими правами он фактически действует
- Именно SUID/SGID меняют эффективный UID/GID процесса, не трогая реальный — так `passwd` "знает", кто его запустил, но действует как root
- Команда `id` показывает оба набора для текущей оболочки, если они различаются

## 8. The Sticky Bit — Липкий бит

Специальный бит для директорий: разрешает удалять или переименовывать файл внутри папки только его владельцу (или root), даже если у остальных есть право записи в саму папку.

```bash
ls -ld /tmp

```

```
Вывод: drwxrwxrwt 10 root root ... /tmp

```

- Буква `t` в конце (вместо `x` у "остальных") — это и есть sticky bit
- Классический пример — папка `/tmp`: все могут туда писать, но удалить чужой файл из неё нельзя
- Без sticky bit право записи на папку позволило бы любому удалить или переименовать в ней даже чужие файлы

```bash
chmod +t shared_folder/ # Установить sticky bit символьно
chmod 1777 shared_folder/ # То же самое числом (1 — код sticky bit)

```
